Build a polished, responsive web app prototype for a Solana community-funded fair-launch memecoin platform.

Core concept

Anyone can propose a meme token inspired by an internet meme or a viral social media post. Every participant can commit exactly $10 worth of USDC to a launch. No participant can contribute more than $10 per launch. Once the required number of valid participants is reached, the launch becomes eligible for token creation and liquidity pool initialization. There is no privileged developer allocation or large-investor tier.

Important: this is a frontend prototype only. Do not transfer real cryptocurrency, request private keys, or pretend blockchain transactions have occurred.

Pages and features

1. Home page with a modern crypto-native design, active launches, completed launches, and a clear explanation of fair launch mechanics.
2. Launch cards showing meme image, token name, creator wallet address, committed amount, number of unique participant wallets, target participant count, deadline, and status.
3. Launch details page with a progress bar, participant list using shortened public wallet addresses, commitment rules, and a Connect Wallet button.
4. A Commit $10 button with a simulated confirmation flow. Clearly label all simulated transactions as demo data.
5. A Propose a Meme form with token name, ticker, image URL, source URL, and description. Do not create a real token.
6. A My Activity page showing demo commitments and their statuses.
7. A clear refund policy section explaining how refunds would work in a future on-chain version.

Design
Use a dark, modern, high-quality crypto interface. Strong typography, clean cards, subtle borders, vivid but restrained accent colors, responsive desktop and mobile layouts. Avoid generic corporate dashboards. Make the product feel like a credible community-owned meme launch platform.

Technical requirements
Use TypeScript and a maintainable component structure. Keep demo data separate from UI components. Include realistic demo launches and clear loading, empty, and error states. Never imply that the prototype has deployed a token, collected funds, or created liquidity.

Start by building the working frontend. Make sure all navigation and demo interactions work before adding any blockchain integration.
